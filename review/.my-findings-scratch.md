F1 [高] probe 端点没有超时控制
- 位置：src/index.ts:3619-3660（for 循环 + await handleChatCompletions）
- 证据：grep "timeout|AbortSignal" 在 3599-3720 区间只匹配到 verdict 的正则，**没有实际超时**
- 影响：qoder 排队预算已提到 60 秒（用户要求）。串行探测 3 个账号最坏 180 秒。
      而内部 Request 未带 signal，客户端的 curl/浏览器早就断了，服务端还在等。
- 建议：给内部 Request 加 `signal: AbortSignal.timeout(N)`，并把超时当 verdict='timeout'
- 工作量：S

- 工作量：M

F4 [中] isWafBlocked 的 CJK 加固会漏判「中文 WAF 拦截页」
- 位置：src/upstream/client.ts 的 isWafBlocked（CJK 排除那行）
- 实测（脚本 /tmp/waf-test.mjs）：
  | 输入 | 判 WAF |
  |---|---|
  | `Forbidden` | true ✅ |
  | `<html>403 Forbidden</html>` | true ✅ |
  | `<html>您的访问被拒绝</html>` | **false ⚠️ 漏判** |
  | `访问被拒绝\nAccess Denied by WAF` | **false ⚠️ 漏判** |
  | `Qoder 服务繁忙：排队…` | false ✅（这是修复目标） |
- 背景：上游是 EdgeOne + APISIX（腾讯技术栈），**存在返回中文拦截页的可能**。
- 后果：真 WAF 时被判成普通 403 → 继续轮转账号 → 撞同一堵墙；且不触发
  WAF_IP_THRESHOLD 的 IP 级全局停服判断。
- 权衡：修复前「100% 我们的中文 ProviderError 被误判成 WAF」（已实际发生多次）；
  修复后「中文 WAF 页漏判」（理论风险，未实际观测到）。**净收益为正，但判据可更精确。**
- 更好判据（建议）：不要用「含 CJK」这种语言特征，改用**内容形态**：
  `/<html|<!doctype/i.test(body)` 或已知 WAF 特征词（`denied|blocked|forbidden|拒绝访问`）。
  语言与「是否 WAF」无因果关系，形态才有。
- 工作量：S
